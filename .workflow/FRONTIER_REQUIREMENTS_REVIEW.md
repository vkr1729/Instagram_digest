# Frontier Requirements Review — Anti-Doomscroll Rebrand

## 0. Scale Anchor (non-negotiable)
- Target: single-person personal use. No multi-tenant DB, no auth server, no sync backend, no microservices, no per-account state machine.
- Control surface stays file-local: `sources.json` + `localStorage` (Web PWA) / SwiftData `DailyProgress`+`AppState` (iOS). No cross-device server sync — each platform enforces quota independently; single-device-at-a-time is the assumed usage.
- "Synchronized across local storage / SwiftData" in REQUIREMENTS §2-D3 must be read as "mirrored schema", not live sync. Anything requiring a backend (OAuth app, PIN recovery server, cross-device quota merge) is out of scope.
- Per taste: functional single-user fit over stringent gates. If a UAT fails >~3 rounds without a crash/data-loss signal, relax the UAT or add a test seam and move on.

## Q1. What counts as "watch time", what is a "day", and where does lockout live?
- **Ambiguity / failure mode:** D3 replaces the 50-reel count with `daily_watch_seconds`, 20 min default, 10/20/30/45 picker, Gentle Pause vs Hard Lockout + emergency PIN. Undefined: does paused / buffering / background-tab / muted-autoplay / scrub-replay / breather-overlay time count? What timezone defines "calendar day"? "Synchronized across local storage / SwiftData" implies cross-platform merge, but the deployed site is static GitHub Pages with no backend — two tabs, private mode, cleared storage, or iOS background audio each bypass or double-count. PIN storage/recovery unspecified — a forgotten PIN with Hard Lockout = self-DoS until tomorrow. Current code (`templates/partials/player.js:84-153` daily count set + snooze key, `DigestState.swift:93-108` `viewedCount/snoozeUntil`) is count-based; no `daily_watch_seconds` exists anywhere yet.
- **Recommended:** Define watch time as summed `timeupdate` deltas while `!paused && !ended && document.visibilityState==='visible'` (web) and `timeControlStatus==.playing && scenePhase==.active` (iOS). Day = local calendar `YYYY-MM-DD`. Each platform keeps its own `daily_watch_seconds + quota_minutes + enforcement_mode + pin_hash` (localStorage date-keyed / SwiftData `DailyProgress` extended fields) — no merge. PIN = local 4-digit salted hash only; forgot-PIN = reinstall/clear accepted for one user, documented. Default enforcement = Gentle Pause; Hard Lockout opt-in only.
- **Alternatives:** (a) Backend-synced quota via `local_server.py` — accurate across devices but breaks static Pages deploy and adds a service for one user; reject. (b) Keep reel-count proxy — trivial but contradicts the time-based goal; reject. (c) Count background/paused time — punishes legitimate pauses, inflates doomscroll guilt metric; reject.

## Q2. If Tier 3 is stripped, who fills the digest on thin anonymous weeks?
- **Ambiguity / failure mode:** D2 removes `extract_external_reels_from_feed` (up to `MAX_EXTERNAL_SHARE=0.40` of capacity) and session-challenge code; routine extraction becomes strictly cookie-free. Anonymous channel grids routinely yield thin weeks (private/deleted handles, login walls, missing timestamps dropped by cutoff, no CDN URL at download). Spec names no depth compensation, no shortfall rule, no change to `MIN_DEPLOY_ITEMS` (150 at defaults). Failure: viability passes but deploy floor fails with no recovery path, or contributor silently lowers the floor to "fill quota" and ships thin archives.
- **Recommended:** Keep `MIN_DEPLOY_ITEMS` hard; below floor → existing `shortfall_paused` stage, zero R2 mutation, weekly file untouched, resume later with deeper `--limit-per-creator` (reuse existing knob, no new env var). Single-user archive trust matters more than quota-filling. State this explicitly — current spec is silent.
- **Alternatives:** (a) Lower the floor for the rebrand — hides shortfall instead of preserving it; reject. (b) Anonymous hashtag/explore pseudo-feed as Tier 3 replacement — reintroduces the exact feed-scrape bot risk the strip was meant to kill, with worse signal; reject.

## Q3. How does one-time interactive onboarding work from a static site with no backend?
- **Ambiguity / failure mode:** D2 promises `python main.py --import-following` AND a dashboard `/channels` button launching an interactive Playwright window that extracts follows into `sources.json` "without persisting long-lived session cookies". Deployed dashboard is static GitHub Pages — no Python, no Playwright, cannot launch a local browser. Also unspecified: 2FA / checkpoint challenges, 500+ follow pagination, dedupe vs existing 100+ handles with `favorite`/`category`/`enabled` preservation, category assignment for imports, and proof of no cookie persistence (which files? `data/cookies.json`, `cookies.txt`, `--cookies-from-browser` fallback). No `import-following` code exists today.
- **Recommended:** CLI is source of truth: headed Playwright with temp `user-data-dir`, user completes login/2FA manually, script scrapes following DOM, merges by lowercased handle (preserve existing `favorite`/`category`/`enabled`; new imports `enabled:true, category:"niche"` for manual triage), closes context, deletes temp dir, asserts no cookie-file write on this path. `/channels` button only active when `window.__IS_LOCAL` (local_server); on Pages it renders "Run `python main.py --import-following` locally" hint.
- **Alternatives:** (a) In-browser Instagram OAuth — needs app registration + backend + token store for one user; reject per scale anchor. (b) Manual CSV/handle paste — zero-login, works everywhere, but tedious at 100+ follows; keep as fallback input to the same merge function, not the primary.

## Q4. Manual Advance + Breather vs 0.5s auto-advance, hold-2x, and watched tracking — what wins?
- **Ambiguity / failure mode:** D5.1 adds manual-advance toggle (stop at reel end until swipe/tap) + optional 3s reflection pause. Existing `player.js` auto-advances 500 ms after `ended` (`handleVideoEnd`), plus IntersectionObserver autoplay, scroll-settle drive, hold-2x latch, 80% watched rule, swipe-up marks-watched. Unspecified: does manual mode disable observer auto-play on scroll-through? Does the 3s breather count toward daily quota? Does tap-to-skip-breather exist? iOS `FeedPlayerCoordinator` has no such mode today — half-migration (web stops, iOS advances) breaks parity matrix. Wedge risk: manual-pause cooldown (`MANUAL_PAUSE_COOLDOWN_MS`) fighting the new stopped-at-end state.
- **Recommended:** Single `advance_mode: 'auto'|'manual'` + `breather_enabled: bool`, persisted in localStorage / `AppState`, default `auto` (preserve muscle memory). Manual: `ended` pauses, shows "Swipe for next ↓" affordance, never calls `advanceToNextReel`; swipe still plays next explicitly. Breather is manual-only, skippable by tap, timer excluded from quota. Mirror the enum in Swift from day one.
- **Alternatives:** (a) Force manual for everyone — strongest anti-doomscroll statement but breaks existing flows and UAT muscle memory; reject as default, allow opt-in. (b) Per-mode timer duplication — doubles playback state machines for one user; reject.

## Q5. Archetypes + Chronological/Unranked mode — where do tags live and what does "unranked" sort?
- **Ambiguity / failure mode:** D5.4/5.5 promises creator tagging (Educational/Craft vs Lifestyle/Vlog) in `/channels` and a toggle hiding `#01` badges + chronological sort "instead of viral velocity". But `sources.json` today uses orthogonal axes: `category` (ai_tech/finance/health/food/entertainment/niche) + `favorite` bool. Is `archetype` a new field, a replacement, or a view? Who tags 100+ creators, what do untagged do under an active filter? Chrono needs reliable `taken_at`, yet the cookie-free pipeline drops timestamp-less reels and marks `metrics_estimated` — chrono may be sparse/misordered. Deepest ambiguity: does "unranked" only hide badges (inclusion still Top-250 by ranker) or truly disable ranking (unbounded chrono list breaks the finite-briefing promise + `MIN_DEPLOY_ITEMS`)?
- **Recommended:** Additive optional field `archetype: "educational"|"craft"|"lifestyle"|"vlog"|null` (null = untagged → shows in All, excluded only when a filter is active). One-time migration maps existing categories to a default (`ai_tech/finance/health/food/niche→educational`, `entertainment→lifestyle`), `/channels` dropdown overrides. Neutrality mode is display-only: ranker still selects the finite Top-250 inclusion set, UI hides badges and offers `sort: rank|chrono` over that set by `taken_at` desc. Document chrono gaps from dateless drops.
- **Alternatives:** (a) Replace `category` with `archetype` — breaks filter chips, progress rings, `MAX_CATEGORY_SHARE`; reject. (b) True unranked (no ranker, pure chrono of all candidates) — unbounded doomscroll feed, contradicts briefing + deploy floor; reject.
